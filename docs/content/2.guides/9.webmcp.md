[WebMCP](https://developer.chrome.com/docs/ai/webmcp) is a proposed web standard that lets a page register tools with the AI agent running in the browser.

Where [MCP](/docs/ai-ready/guides/mcp) serves agents connecting to your server, WebMCP serves the agent already on the page: it can search your content, fill your forms and drive your UI through functions you define instead of guessing at the DOM.

::caution
WebMCP is an origin trial from Chrome 149. Everything here degrades to a no-op in browsers without `document.modelContext`{lang="ts"}, so it is safe to ship today. Enable `chrome://flags/#enable-webmcp-testing`{lang="bash"} to test locally.
::

## Site Tools

Enable `webmcp`{lang="ts"} to register three read-only tools that expose your indexed content to the agent:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  aiReady: {
    webmcp: true,
  },
})
```

| Tool | Description |
|------|-------------|
| `list_pages` | Routes, titles and descriptions, with paging |
| `search_pages` | Full-text search across page content |
| `get_page_markdown` | Reads a route as markdown |

They read the same database as the MCP server, so they need prerendered or [runtime indexed](/docs/ai-ready/guides/runtime-indexing) data. The tools call a public `/__ai-ready/pages`{lang="bash"} endpoint that only returns content already published through `llms.txt` and your `.md` routes.

All three carry the `readOnlyHint`{lang="ts"} and `untrustedContentHint`{lang="ts"} annotations. They never change state, and the agent treats page content as untrusted input.

## Your Own Tools

`useWebMcpTool()`{lang="ts"} registers a tool for the lifetime of the current component. Enabling `webmcp`{lang="ts"} auto-imports it, with or without the built-in site tools.

```vue [app/pages/products.vue]
<script setup lang="ts">
const maxPrice = ref(Infinity)

useWebMcpTool({
  name: 'filter_products',
  title: 'Filter products',
  description: 'Filters the visible product list by a maximum price.',
  inputSchema: {
    type: 'object',
    properties: {
      maxPrice: { type: 'number', description: 'Highest price to show, in dollars.' },
    },
    required: ['maxPrice'],
  },
  annotations: { readOnlyHint: true },
  execute: ({ maxPrice: price }) => {
    maxPrice.value = price
    return `Showing products under $${price}.`
  },
})
</script>
```

Unregistering happens automatically when the component unmounts, so agents only see tools for the state the page is in. Keep registration static where you can: [Chrome recommends](https://developer.chrome.com/docs/ai/webmcp/best-practices) it as the default, since each tool costs context window.

`execute`{lang="ts"} may return a string, or an MCP-style result when you need to flag a failure:

```ts
execute: async ({ sku }) => {
  const added = await cart.add(sku)
  if (!added) {
    return {
      content: [{ type: 'text', text: `${sku} is out of stock. Call search_products to find an alternative.` }],
      isError: true,
    }
  }
  return `Added ${sku} to the cart.`
}
```

Errors should tell the model how to recover. Validate strictly in code and loosely in the schema, so an agent that sends `about`{lang="ts"} instead of `/about`{lang="ts"} still gets an answer.

Use `isWebMcpSupported()`{lang="ts"} when you want to show agent-specific UI:

```ts
const showAgentHints = isWebMcpSupported()
```

## Forms

The declarative API turns an annotated form into a tool without any JavaScript. Enabling `webmcp`{lang="ts"} adds the attribute types to your templates.

```vue
<template>
  <form
    toolname="add_to_timesheet"
    tooldescription="Reports a billable task and its hours to the timesheet."
    toolautosubmit
    @submit="onSubmit"
  >
    <input name="task" toolparamdescription="What was worked on.">
    <input name="hours" type="number" toolparamdescription="Hours spent, such as 3.5.">
    <button type="submit">
      Add
    </button>
  </form>
</template>
```

Return a result to the agent with `respondWith()`{lang="ts"}, which requires cancelling the native submit first:

```ts
function onSubmit(event: SubmitEvent) {
  if (!event.agentInvoked)
    return
  event.preventDefault()
  event.respondWith?.(save(new FormData(event.target as HTMLFormElement)))
}
```

The `toolactivated`{lang="ts"} and `toolcancel`{lang="ts"} events fire when an agent fills in or abandons the form, and the `:tool-form-active`{lang="css"} and `:tool-submit-active`{lang="css"} pseudo-classes let you show it happening.

## Security

Tools are same-origin by default. Cross-origin exposure is opt-in and, per [Chrome's guidance](https://developer.chrome.com/docs/ai/webmcp/secure-tools), should only ever list origins you trust, since they gain whatever access the tool grants.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  aiReady: {
    webmcp: {
      exposedTo: ['https://partner.example.com'],
    },
  },
})
```

Prompt injection is the risk that matters here: page content can carry instructions aimed at the agent. Annotate anything returning user-generated or third-party content with `untrustedContentHint`{lang="ts"}, and anything that changes state without `readOnlyHint`{lang="ts"} so the agent knows to confirm with the user first.

Tool output is truncated to 1,500 characters to stay within agent guardrails, with a pointer to the full source. Raise it if your pages need more:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  aiReady: {
    webmcp: {
      maxOutputChars: 4000,
    },
  },
})
```

The same budgets apply to your own tools: names of 30 characters, descriptions of 500, parameter descriptions of 150. `useWebMcpTool()`{lang="ts"} warns in development when a tool goes over.

## Testing

Agent behaviour is probabilistic, so a passing unit test does not mean an agent will call your tool correctly. Chrome's [evals guide](https://developer.chrome.com/docs/ai/webmcp/evals) covers writing evaluations for tool selection, argument shape and multi-step journeys. The [Model Context Tool Inspector](https://developer.chrome.com/docs/ai/webmcp) extension shows which tools a page has registered.
