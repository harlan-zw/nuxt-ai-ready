## Introduction

Nuxt AI Ready v3 supports Nuxt 4.6 and Nuxt 5. It ships in [Nuxt SEO v6](/docs/nuxt-seo/releases/v6).

Nuxt SEO v6 installs AI Ready by default. It uses AI Ready's own defaults and overrides no option ([nuxt-seo#666](https://github.com/harlan-zw/nuxt-seo/pull/666)).
To turn the module off inside Nuxt SEO, set `aiReady: false`.

Markdown negotiation now varies only on the `Accept` header by default.
Root `skills/` directories are no longer published.
Check the [breaking changes](#breaking-changes) before upgrading.

For a guided migration, use the [LLM upgrade prompt](#llm-upgrade-prompt) with Claude or [ChatGPT](https://chatgpt.com).

::tip
Coming from v1? Apply the [v2 IndexNow change](/docs/ai-ready/releases/v2) first, then this page.
::

## 🧭 Accept-Only Negotiation

A request that prefers `text/markdown` still receives the Markdown twin of a page. ([#160](https://github.com/harlan-zw/nuxt-ai-ready/pull/160))
AI bot User-Agents no longer select Markdown by default.
Your caches now need only the `Accept` header in their key.
User-Agent variation split identical HTML responses into many cache entries.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/docs/**': {
      cache: { maxAge: 3600, varies: ['accept'] },
    },
  },
})
```

To keep bot detection, set `aiReady: { botNegotiation: true }`. See [Accept-Only Negotiation](#accept-only-negotiation-default) below.

## 🚨 Configuration Warnings

The module checks your configuration in development and at build time. Each warning names its fix. ([#160](https://github.com/harlan-zw/nuxt-ai-ready/pull/160))

- A missing or local `site.url`.
- An ISR or response cache route rule that turns off negotiation.
- A cache rule with no `accept` entry in `cache.varies`.
- Static output that cannot run negotiation middleware.
- `contentNegotiation: true` that overrides cache protection.

## 🧩 Typed Runtime Imports

Import app functions from `#ai-ready/app` and server functions from `#ai-ready/server`. ([#148](https://github.com/harlan-zw/nuxt-ai-ready/pull/148))
The module keeps its auto-imports and the `#ai-ready` alias.

```ts [server/api/search.get.ts]
import { searchPages } from '#ai-ready/server'

export default defineEventHandler(event => searchPages(event, 'nuxt seo', { limit: 5 }))
```

## 🛰️ Named Discovery Entries

Generated discovery catalogs now include display names and named ARD entries. ([#158](https://github.com/harlan-zw/nuxt-ai-ready/pull/158))
The MCP handshake and `llms.txt` carry default guidance for the page tools.
Custom instructions stay in place.

Markdown twins keep `Vary: Accept` after a negotiated redirect, on runtime and static pages. ([#159](https://github.com/harlan-zw/nuxt-ai-ready/pull/159))

## ⚡ Lighter Requests

The module selects its storage implementation at build time. ([#153](https://github.com/harlan-zw/nuxt-ai-ready/pull/153))
With the database disabled, matched production requests loaded 73 [Drizzle](https://orm.drizzle.team) files (247,518 source bytes) before this change. They now load none.
Negotiation runs once per request. For 100 SSR requests, header parsing and route lookups fell from 200 to 100.

`Link` header construction also reuses i18n and Site Config work. ([#154](https://github.com/harlan-zw/nuxt-ai-ready/pull/154), [#155](https://github.com/harlan-zw/nuxt-ai-ready/pull/155))

## ⚠️ Breaking Changes

### Nuxt 4.6 and Node 22.22.3

AI Ready v3 requires Nuxt `^4.6.0 || ^5.0.0`. ([#148](https://github.com/harlan-zw/nuxt-ai-ready/pull/148))
It also requires Node `^22.22.3 || ^24.15.0 || >=26.0.0`.
v2 declared Nuxt `>=4.0.0`.

### `better-sqlite3` Removed

[SQLite](https://sqlite.org) now uses the built-in `node:sqlite` module only. ([#148](https://github.com/harlan-zw/nuxt-ai-ready/pull/148))
The `better-sqlite3` fallback and its optional peer dependency are gone.
[Bun](https://bun.sh) uses `bun:sqlite`. [Cloudflare](https://cloudflare.com) uses D1.

```bash
# Before: Node versions without node:sqlite needed the fallback
pnpm add better-sqlite3

# After: remove it if only AI Ready used it
pnpm remove better-sqlite3
```

### Accept-Only Negotiation Default

AI bot User-Agents no longer get Markdown when their `Accept` header prefers HTML. ([#160](https://github.com/harlan-zw/nuxt-ai-ready/pull/160))
Negotiated responses send `Vary: Accept`. v2 sent `Vary: Accept, Sec-Fetch-Dest, User-Agent`.
A cached route keeps negotiation when its `cache.varies` includes `accept`.

```ts [nuxt.config.ts]
// Before: v2 needed all three inputs in the cache key
export default defineNuxtConfig({
  routeRules: {
    '/docs/**': { cache: { maxAge: 3600, varies: ['accept', 'sec-fetch-dest', 'user-agent'] } },
  },
})

// After: v3 needs only Accept
export default defineNuxtConfig({
  routeRules: {
    '/docs/**': { cache: { maxAge: 3600, varies: ['accept'] } },
  },
})
```

To keep bot detection, set `botNegotiation: true`. Your Nitro and CDN caches must then vary on all three inputs.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  aiReady: { botNegotiation: true },
  routeRules: {
    '/docs/**': { cache: { maxAge: 3600, varies: ['accept', 'sec-fetch-dest', 'user-agent'] } },
  },
})
```

If your CDN cannot vary on `Accept`, set `aiReady: { contentNegotiation: false }` and link explicit `.md` URLs.

### Markdown URLs Skip Response Caching on Nitro 3

On Nitro 3, the module adds a `/**.md` route rule with `cache: false`. ([#160](https://github.com/harlan-zw/nuxt-ai-ready/pull/160))
Nitro 3 response caches call the page handler without global middleware.
The rule keeps Markdown conversion in place. Nitro 2 builds do not change.

### Root `skills/` No Longer Published

Discovery now scans public directories only. ([#163](https://github.com/harlan-zw/nuxt-ai-ready/pull/163))
Root `skills/` folders can hold private instructions for coding agents.
v2 published them by default.

```text
# Before: published by default
skills/seo-audit/SKILL.md

# After: published by default
public/skills/seo-audit/SKILL.md
```

To keep publishing root skills, set the directory explicitly:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  aiReady: {
    agentSkills: { dir: 'skills' },
  },
})
```

### Module Dependency Versions

AI Ready installs these modules as dependencies. The minimum versions changed. ([#148](https://github.com/harlan-zw/nuxt-ai-ready/pull/148), [#162](https://github.com/harlan-zw/nuxt-ai-ready/pull/162))

- **@nuxtjs/robots** v7: [release notes](/docs/robots/releases/v7)
- **@nuxtjs/sitemap** v9: [release notes](/docs/sitemap/releases/v9)
- **nuxt-site-config** v5: [breaking changes](https://github.com/harlan-zw/nuxt-site-config/releases/tag/v5.0.0)
- **nuxtseo-shared** v6

### DevTools Needs `nuxtseo-devtools-host`

The DevTools panel now loads from a separate package. Install it as a dev dependency to keep the AI Ready tab.

```bash
pnpm add -D nuxtseo-devtools-host
```

Without it, the AI Ready tab shows an install button for the package. Production builds do not change.

````markdown
# Upgrade Guide: nuxt-ai-ready v2 to v3.0.0

You are helping me upgrade nuxt-ai-ready from v2 to v3.0.0 in my Nuxt project.
If the project uses @nuxtjs/seo, upgrade @nuxtjs/seo to v6 instead. It includes nuxt-ai-ready v3.

## Requirements

- Nuxt `^4.6.0 || ^5.0.0`
- Node `^22.22.3 || ^24.15.0 || >=26.0.0`

## Breaking Changes

### 1. better-sqlite3 Removed

**What changed:** [SQLite](https://sqlite.org) uses `node:sqlite` only. The `better-sqlite3` fallback is gone.

**Search my codebase for:** `better-sqlite3`

**Action:** Remove `better-sqlite3` from package.json if nothing else uses it.

### 2. Accept-Only Negotiation

**What changed:** AI bot User-Agents no longer get Markdown by default. Responses vary only on `Accept`.

**Search my codebase for:** `varies`, `sec-fetch-dest`, `user-agent`, `contentNegotiation`

**Regex pattern:** `varies:\s*\[[^\]]*['"]user-agent['"]`

**Before:**
```ts
routeRules: { '/docs/**': { cache: { maxAge: 3600, varies: ['accept', 'sec-fetch-dest', 'user-agent'] } } }
```

**After:**
```ts
routeRules: { '/docs/**': { cache: { maxAge: 3600, varies: ['accept'] } } }
```

**Action:** Ask me whether to keep bot detection. If yes, set `aiReady: { botNegotiation: true }` and keep all three `varies` entries.

### 3. Root skills/ No Longer Published

**What changed:** Agent skill discovery scans `public/skills/<name>/SKILL.md` only.

**Search my codebase for:** files matching `skills/*/SKILL.md` outside `public/`

**Action:** Ask me which skills are public. Move public skills to `public/skills/<name>/SKILL.md`. Or set `aiReady: { agentSkills: { dir: 'skills' } }` to keep the old folder.

### 4. Module Dependency Versions

**What changed:** AI Ready requires @nuxtjs/robots v7, @nuxtjs/sitemap v9, nuxt-site-config v5, and nuxtseo-shared v6.

**Search my codebase for:** `@nuxtjs/robots`, `@nuxtjs/sitemap`, `nuxt-site-config` in package.json

**Action:** Upgrade any direct dependency on these packages to the listed major.

### 5. DevTools Host Package

**What changed:** The DevTools panel needs `nuxtseo-devtools-host`.

**Action:** If I use Nuxt DevTools, add `nuxtseo-devtools-host` as a dev dependency.

## Optional

Replace server imports from `#ai-ready` with `#ai-ready/server`, and app imports with `#ai-ready/app`.

**Regex pattern:** `from ['"]#ai-ready['"]`

## Verification Checklist

1. `pnpm install` (update lockfile)
2. `npx nuxt typecheck` (catch type errors)
3. `pnpm build` (read the AI Ready configuration warnings)
4. `curl -H 'Accept: text/markdown' -D - -o /dev/null <url>` returns a redirect to the `.md` URL
5. `/llms.txt` and one `.md` page load on the preview server
````

## ✅ Upgrading

If you use `@nuxtjs/seo`, upgrade it to v6. It includes AI Ready v3.

```bash
# pnpm
pnpm add nuxt-ai-ready@^3

# npm
npm install nuxt-ai-ready@^3

# yarn
yarn add nuxt-ai-ready@^3
```
